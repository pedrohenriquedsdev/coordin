# Tasks — demand-screens

Regras para todas as tasks:
- **Quem implementa pode ser um modelo mais simples: siga o texto de cada task à risca, copiando o padrão do arquivo indicado.** Se algo não estiver claro, pare e pergunte; não invente comportamento fora das specs.
- Só `src/coordin-web` muda (e, no fim, `CLAUDE.md`). Nenhum pacote novo (npm), nenhuma mudança na API, no cliente gerado ou na CI. Se surgir a necessidade de instalar algo, pause e peça a autorização do autor (`CLAUDE.md` §11).
- Padrões a copiar: *store* de `teams/teams.store.ts` e `calendar/calendar.store.ts` (`HttpClient` + `ApiConfiguration.rootUrl`, `signal`s, `status: 'loading' | 'ready' | 'failed'`, recarregar depois de cada escrita, conversão `Number(...)` das respostas geradas); página de `calendar/calendar-page.ts` (estados Carregando / falha com "Tentar de novo"); formulário e mensagens de `calendar/absences-section.ts` (`NonNullableFormBuilder`, `messageFor(readProblem(error), fallback)`, `saving`/`message`); testes de `calendar/calendar-page.spec.ts` (`HttpTestingController`, `provideApiConfiguration('')`, `provideLocalePtBr()`, `afterEach(() => http.verify())`).
- Funções geradas: `getSchedule`, `getDemands`, `getDemand`, `createDemand`, `updateDemand`, `deleteDemand`, `reorderDemands`, `completeDemand`, `getSettings`, `updateSettings` em `src/app/api/fn/...`, sempre no formato `fn(this.http, this.root, { id, body })`. Os números das respostas vêm como `number | string`: converta com `Number(...)` (e preserve `null`).
- Comentários e textos para o usuário em português (pt-BR); identificadores em inglês. Datas de calendário são texto `yyyy-MM-dd`: **nunca** `Date`, `DatePipe` nem `new Date(texto)`; use `CalendarDatePipe`/`formatCalendarDate` e `Clock` de `core/dates`. Estado e alertas sempre com **texto**, nunca só cor. HTML e Tailwind são escritos como nas telas de `teams/` e `calendar/`.
- Ao fim de cada grupo, rode em `src/coordin-web`: `npm run lint`, `npm run format:check` (se falhar, `npm run format`), `npm test -- --watch=false` e `npm run build`; tudo verde. O autor recebe **uma** lista de comandos de commit por grupo, com as marcações deste `tasks.md` dentro do commit do código. Cada commit compila e passa nos testes sozinho.
- Nenhum dado real ou segredo no repositório, nem nos testes. Verificações manuais com credenciais usam banco descartável e só rodam com a autorização do autor.
