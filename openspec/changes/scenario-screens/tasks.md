# Tasks — scenario-screens

Regras para todas as tasks:
- **Quem implementa pode ser um modelo mais simples: siga o texto de cada task à risca, copiando o padrão do arquivo indicado.** Se algo não estiver claro, pare e pergunte; não invente comportamento fora das specs.
- **Nenhuma dependência nova** (npm ou NuGet): o `chart.js` e o `ChartComponent` já existem. Qualquer pacote novo exige pausa e a autorização do autor (`CLAUDE.md` §11). **Nada no back-end, no banco, no cliente gerado (`src/app/api/`) nem na CI muda.**
- Padrões a copiar: estado e tela (`schedule/schedule.store.ts`, `schedule-page.*`, `demands/demands.store.ts`, `demands-page.*`, `demands/demand-form.store.ts`, `demand-form-page.*`); gráfico (`reports/team-report-chart.ts`, `charts/chart.component.ts` e o dublê `charts/chart-test-double.ts`, injetado por `CHART_FACTORY`); textos (`planning/labels.ts`); datas (`core/dates/calendar-date.ts`); erros (`core/problems`); confirmação inline em dois passos (botão "Confirmar exclusão" em `demands-page.html`).
- Comentários e textos ao usuário em português (pt-BR); identificadores em inglês. **Datas de calendário:** texto `yyyy-MM-dd`, formatadas por `core/dates`, nunca `Date`, `new Date(texto)` ou `DatePipe`. Números `number | string` do cliente viram `number` **no mapeamento** (`Number(...)`), nunca no template. Estado e alerta sempre em texto, nunca só em cor.
- **A tela não tem regra de negócio:** não recalcula pontuação, datas nem diferenças; só mostra o que a API devolve. Nenhuma chamada a `apply` ou `reset-to-priority` sem o segundo clique de confirmação.
- **Testes:** funções puras com Vitest simples; *stores* e telas com `HttpTestingController`; o gráfico com o `CHART_FACTORY` de teste (não use `vi.mock` de módulo, nem `vi` em arquivo de apoio dentro de `src/app`). Cada tela cobre: carregando, falha com "Tentar de novo", caminho feliz, mensagem de erro da API e **"nada é chamado sem confirmação"**.
- Ao fim de cada grupo, em `src/coordin-web`: `npm run format:check`, `npm run lint`, `npm test -- --watch=false` e `npm run build` (o aviso de orçamento do bundle já existe desde a change 8) e mantenha tudo verde; se o formato falhar, rode `npx prettier --write` nos arquivos tocados. O .NET não muda, mas o CI o roda mesmo assim.
- Marque cada task em `tasks.md` ao concluí-la, no mesmo commit do código e dos testes do grupo.
- Nenhum dado real ou segredo no repositório, nem nos testes. A verificação manual usa API local e banco descartável, só com a autorização do autor.
